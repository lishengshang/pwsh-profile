# 文档导航与维护约定

本文说明文档分工、术语与更新方式。首次安装从[项目首页](../README.md)开始，开发硬约束以根目录 [AGENTS.md](../AGENTS.md) 为准。

## 阅读入口

| 文档 | 回答的问题 | 维护范围 |
|---|---|---|
| [使用速查](usage.md) | 日常如何使用与同步 | 用户命令、操作示例、生效方式 |
| [配置参考](reference.md) | 安装哪些内容、参数与开关如何生效 | 组件、依赖、配置路径、链接模式与保护边界 |
| [常见问题](faq.md) | 出现错误时如何定位与恢复 | 症状、检查步骤、恢复方法 |
| [维护与验证](maintenance.md) | 如何检查、验证和交付改动 | 维护流程、验证范围与证据要求 |

长期待办放在 [TODO.md](../TODO.md)，已完成改动与原因保留在 Git 历史和 PR 中。文档不保存会话记录、临时调试日志或未经验证的完成结论。

## 单源维护

- 开发硬约束只在 [AGENTS.md](../AGENTS.md) 维护；本文约定文档组织方式，不另建一套开发规则。
- 用户命令完整清单维护在 `usage.md`；项目首页只展示高频子集。
- setup 参数说明维护在 `reference.md`「参数一览」；bootstrap 参数说明维护在脚本帮助，使用 `Get-Help .\bootstrap.ps1 -Detailed` 查看。
- 工具与模块安装清单以 `setup.ps1` 为实现来源，配置链接清单以 `Scripts/Get-ManagedLinks.ps1` 为实现来源；变更时同步更新参考文档。
- 故障处理集中在 `faq.md`，其他文档通过链接引用，避免复制多份恢复步骤。

## 术语

| 术语 | 含义 |
|---|---|
| profile | PowerShell 启动配置；入口为 `Microsoft.PowerShell_profile.ps1` |
| 仓库目录 | Git 克隆位置，保存受版本控制的源配置 |
| 安装目录 | 当前 PowerShell 的 `$PROFILE` 所在目录，可与仓库目录相同 |
| Core 条目 | 始终部署的 profile 本体配置；不同于可选择的 `core` 安装组件 |
| 受管目标 | setup 建立或确认并登记的配置目标；历史登记不能证明其当前仍属于仓库 |
| 链接注册表 | 本机 `linked-targets.json` 状态文件，不是 Windows 注册表 |
| 降级 | 依赖或链接能力不可用时，按已说明的范围回退或跳过 |

## 编写与变更检查

Markdown 使用 UTF-8 编码，每篇只保留一个一级标题，按二级、三级标题组织。代码块标注语言；本地文档使用行内形式的相对 Markdown 链接，标题锚点指向真实章节。代码路径、命令、参数和环境变量使用行内代码，不写个人绝对路径。

描述行为时同时说明前提、结果和限制，区分已实现行为、可选增强与待办。没有命令的功能应写“改用某命令”或“不可用”，不要笼统写成自动回退。性能数据必须说明环境、测量范围和缓存状态；测试通过不能写成所有交互路径已经验收。

修改后运行文档门禁，并按[维护与验证](maintenance.md)执行受影响的检查。文档门禁检查命令与工具覆盖、一级标题数量、本地链接及标题锚点；它不验证外部网站是否可达，也不能代替人工核对参数语义和运行行为。
